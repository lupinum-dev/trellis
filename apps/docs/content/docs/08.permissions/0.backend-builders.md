Backend builders are the lower-level Convex registration API. In `0.3`, new app
code should usually define behavior with `operation.query(...)`,
`operation.mutation(...)`, `operation.publicMutation(...)`, and
`operation.destructive(...)` from
`@lupinum/trellis/app`, then register the operation with one of these lanes.

Use this page when you are wiring `convex/functions.ts`, reviewing an advanced
escape hatch, or registering a handler that intentionally does not need an
operation.

```ts [convex/functions.ts]
import { defineTrellis } from '@lupinum/trellis/backend'

import { mutation as generatedMutation, query as generatedQuery } from './_generated/server'

export const { query, mutation } = defineTrellis({
  query: generatedQuery,
  mutation: generatedMutation,
})
```

`query` and `mutation` are lane containers. They are not callable root builders.
Every registered handler or operation declares its trust lane at the call site.

## Pick the lane first

| Lane                                             | Use it when                                                                                        |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| `query.public(...)`                              | Anyone may read an explicitly public table                                                         |
| `mutation.public(operation.publicMutation(...))` | Anyone may enter an operation-backed public write                                                  |
| `query.authenticated(...)`                       | The read needs a non-anonymous caller but no workspace assumption                                  |
| `mutation.authenticated(...)`                    | The write needs a non-anonymous caller but no workspace assumption                                 |
| `query.workspace(...)`                           | The read requires a concrete permission and resolved `appIdentity.workspaceId` before `load` runs  |
| `mutation.workspace(...)`                        | The write requires a concrete permission and resolved `appIdentity.workspaceId` before `load` runs |
| `query.protected(...)`                           | The handler needs a custom guard predicate that is not a standard signed-in or workspace lane      |
| `mutation.protected(...)`                        | The handler needs a custom guard predicate that is not a standard signed-in or workspace lane      |
| `transportMutation.authenticated(...)`           | A trusted transport execute mutation needs a non-anonymous forwarded caller                        |
| `query.unsafe(...)` / `mutation.unsafe(...)`     | The handler intentionally leaves the normal lane shape                                             |

The old shape "leave out the guard and maybe it is public" does not exist in
current Trellis. Public, authenticated, workspace, protected, and unsafe are
explicit.

## Public handlers

Public handlers are for data and writes that truly do not need a signed-in
caller or app appIdentity.

`ctx.db` in a public query is read-only and table-limited. Declare the exact
tables on that handler with `reads`. Tables are private by default.

```ts [convex/features/todos/domain.ts]
export const list = query.public({
  reads: ['todos'],
  args: {},
  handler: async (ctx) => {
    return await ctx.db.query('todos').order('desc').collect()
  },
})
```

Public writes do not use `ctx.db` writes. Define the write as
`operation.publicMutation(...)`, declare `publicWrite.reason` and
`publicWrite.tables`, then call the narrow method exposed on `ctx.publicWrite`.

```ts [convex/features/todos/domain.ts]
export const createTodoOp = operation.publicMutation({
  id: 'todos.create',
  args: createTodo.args,
  publicWrite: {
    reason: 'Public todo demo allows anonymous todo creation.',
    tables: ['todos'],
    access: ({ db, args }) => ({
      createTodo: async () =>
        await db.insert('todos', {
          title: args.title,
          completed: false,
          createdAt: Date.now(),
        }),
    }),
  },
  handler: async (ctx) => {
    return await ctx.publicWrite.createTodo()
  },
})

export const create = mutation.public(createTodoOp)
```

Use public lanes for the smallest public starter path. Do not use them to avoid
auth setup. If the answer depends on who is calling, use an authenticated or
workspace lane.

## Authenticated and workspace handlers

Use `authenticated` for signed-in work that has no workspace assumption. Use
`workspace` when the handler must have a concrete permission and a resolved
`appIdentity.workspaceId` before it loads data.

Both lanes own the signed-in boundary. Do not add `guard: authRequired`; that
sentinel is internal lane machinery, not public application API.

```ts [convex/features/workspaces/domain.ts]
export const create = mutation.authenticated({
  args: createWorkspace.args,
  handler: async (ctx, args) => {
    const caller = await ctx.caller()
    // Create the first workspace for this signed-in caller.
  },
})
```

```ts [convex/features/todos/domain.ts]
import { definePermission } from '@lupinum/trellis/auth'

const todoCreate = definePermission({
  key: 'todos.create',
  check: (appIdentity) => appIdentity.workspaceId !== undefined,
})

export const create = mutation.workspace({
  args: createTodo.args,
  permission: todoCreate,
  handler: async (ctx, args) => {
    const appIdentity = await ctx.appIdentity()

    return await ctx.db.insert('todos', {
      workspaceId: appIdentity.workspaceId,
      title: args.title,
      completed: false,
      createdAt: Date.now(),
    })
  },
})
```

## Protected handlers

`protected(...)` is for intentional custom guard predicates. Normal signed-in
code should prefer `authenticated(...)`; normal tenant-scoped app code should
prefer `workspace(...)`.

Protected handlers run the full Trellis backend path:

1. caller
2. appIdentity
3. guard
4. load
5. authorize
6. handler

```ts [convex/features/todos/domain.ts]
export const createFromImport = mutation.protected({
  args: importTodo.args,
  guard: integrationTodoWriter,
  handler: async (ctx, args) => {
    const appIdentity = await ctx.appIdentity()

    return await ctx.db.insert('todos', {
      ownerId: appIdentity.userId,
      title: args.title,
      completed: false,
      source: 'integration',
      createdAt: Date.now(),
    })
  },
})
```

The guard answers the external/custom question. `load` and `authorize` answer
the record-specific question. If the broad question is just "does this
appIdentity have a workspace permission?", use `workspace(...)` instead.

```ts
export const rename = mutation.protected({
  args: renameProject.args,
  guard: integrationProjectWriter,
  load: async (ctx, args) => {
    const project = await ctx.db.get(args.projectId)
    requireRecord(project, 'Project')
    return { project }
  },
  authorize: {
    label: 'project belongs to appIdentity workspace',
    check: (appIdentity, { project }) => project.workspaceId === appIdentity.workspaceId,
  },
  handler: async (ctx, args) => {
    await ctx.db.patch(args.projectId, { name: args.name })
  },
})
```

Missing appIdentity wiring is a setup error. A resolved `null` appIdentity is normal
unauthorized state unless the guard explicitly accepts anonymous callers.

## Unsafe handlers

Unsafe lanes are review-sensitive escape hatches. They require typed permit
metadata.

```ts
import { unsafe } from '@lupinum/trellis/backend'

export const generateUploadUrl = mutation.unsafe({
  permit: unsafe.permit({
    kind: 'preTenantUpload',
    reason: 'Generate upload URLs before a tenant-scoped asset record exists.',
    scope: ['assets'],
  }),
  args: {},
  handler: async (ctx) => {
    requireAuth(await ctx.appIdentity())
    return await ctx.storage.generateUploadUrl()
  },
})
```

Prefer a named capability when only data access crosses tenants:

```ts
export const agencyDashboard = query.protected({
  args: {},
  guard: agencyAdmin,
  crossTenant: {
    reason: 'Agency dashboard spans multiple client workspaces.',
    tables: ['memberships', 'workspaces'],
    access: ({ db }) => ({
      listMemberships: async () => await db.query('memberships').collect(),
    }),
  },
  handler: async (ctx) => {
    return await ctx.crossTenant.listMemberships()
  },
})
```

If the custom-guard handler shape still works and only the database tenant
boundary needs to be crossed, keep that explicit lane and declare the
capability at the export.

## Register operations

Operations are the beginner app authoring path. Backend builders register those
operations with Convex.

```ts
export const remove = mutation.workspace(removeTodoOp)
export const previewRemove = mutation.workspace(previewOf(removeTodoOp))
```

See [Operations](/docs/permissions/operations) for defining operation behavior.

## Common pitfalls

- Writing `query({ ... })` or `mutation({ ... })` instead of an explicit lane.
- Treating a missing guard as public.
- Using `mutation.unsafe(...)` to avoid modeling an appIdentity or tenant.
- Hiding cross-tenant access in a helper where reviewers cannot see why the
  boundary changed.
- Teaching low-level handler objects as the default beginner authoring path.
