---
title: 'Call patterns'
description: 'The normal Trellis call paths in one place.'
---

Trellis has a small set of app call paths. Use the direct path that matches the
caller. Do not add bridge files, forwarded identity, MCP tools, or server
wrappers when an explicit Convex lane is enough.

## Browser reads

Public reads use public handlers:

```ts [convex/features/docs/domain.ts]
export const listPublicDocs = query.public({
  args: {},
  handler: async (ctx) => {
    return await ctx.db
      .query('docs')
      .withIndex('by_visibility', (q) => q.eq('visibility', 'public'))
      .collect()
  },
})
```

Signed-in reads use authenticated handlers and `appIdentity`:

```ts [convex/features/tasks/domain.ts]
import { requireAuth } from '@lupinum/trellis/auth'

export const listTasks = query.authenticated({
  args: {},
  handler: async (ctx) => {
    const appIdentity = await ctx.appIdentity()
    requireAuth(appIdentity)
    return await ctx.db
      .query('tasks')
      .withIndex('by_owner', (q) => q.eq('ownerId', appIdentity.userId))
      .collect()
  },
})
```

## Browser writes

Use authenticated mutations for normal signed-in app work:

```ts [convex/features/tasks/domain.ts]
import { requireAuth } from '@lupinum/trellis/auth'

export const createTask = mutation.authenticated({
  args: createTaskArgs,
  handler: async (ctx, args) => {
    const appIdentity = await ctx.appIdentity()
    requireAuth(appIdentity)
    return await ctx.db.insert('tasks', {
      title: args.title,
      ownerId: appIdentity.userId,
      createdAt: Date.now(),
    })
  },
})
```

`appIdentity.userId` is the local `users._id`. It is not a session profile id, provider subject, or `authKey`.

## Server calls

Nuxt server routes should use server Convex helpers:

```ts [server/api/tasks/export.get.ts]
export default defineEventHandler(async (event) => {
  return await serverConvexQuery(
    event,
    api.features.tasks.domain.listForExport,
    {},
    {
      auth: 'required',
    },
  )
})
```

Server-to-server forwarding is being replaced in Trellis 0.3.0 with an opaque
proof object and backend-revalidated delegation evidence. Do not copy old
forwarded-caller snippets into new apps; use ordinary authenticated server
calls until the new proof API is available.

Forwarded `user:*` subjects use local `users._id` once the 0.3 proof path is
available.

## Permissions

Project permission state from Convex:

```ts [convex/permissions/context.ts]
export const getAccessContext = query.public(
  defineAccessContext({
    resolve: getAppIdentity,
    permissions,
    extend: async (ctx, appIdentity) => {
      const user = await ctx.db.get(appIdentity.userId)
      return {
        email: user?.email ?? null,
        displayName: user?.displayName ?? null,
      }
    },
  }),
)
```

Then read it in Nuxt:

```ts [app/components/Toolbar.vue]
const { can } = useAccess()
const canCreateTask = can(taskCreate)
```

## Destructive operations

Use operations when one action needs the same preview, confirmation, execute path, tests, and MCP behavior:

```ts [convex/features/tasks/operations.ts]
export const deleteTaskOp = defineOperation({
  id: 'tasks.delete',
  kind: 'destructive',
  args: { id: v.id('tasks') },
  load: async (ctx, args) => {
    const appIdentity = await ctx.appIdentity()
    requireAuth(appIdentity)
    const task = await ctx.db.get(args.id)
    if (!task || task.ownerId !== appIdentity.userId) {
      throw new Error('Task not found.')
    }
    return { task }
  },
  preview: async (_ctx, _args, { task }) =>
    operationPreview({
      summary: `Delete "${task.title}"`,
      effects: [
        operationEffect({
          kind: 'delete',
          summary: 'Delete task',
          target: 'task',
          count: 1,
        }),
      ],
      confirm: { id: task._id },
    }),
  handler: async (ctx, args) => {
    await ctx.db.delete(args.id)
  },
})

export const previewDeleteTask = mutation.authenticated(previewOf(deleteTaskOp))
export const deleteTask = mutation.authenticated(deleteTaskOp)
```

## MCP projection

Reads can use `tool.query(...)`. Bounded writes can use `tool.mutation(...)`. Destructive or sensitive work should use `tool.operation(...)`:

```ts [server/mcp/tools/delete-task.ts]
export default tool.operation(deleteTaskOp, {
  execute: executeOperationRef(deleteTaskOp, api.features.tasks.operations.deleteTask),
  preview: previewOperationRef(deleteTaskOp, api.features.tasks.operations.previewDeleteTask),
  previewOperation: 'mutation',
})
```

Run this when the shape changes:

```bash
pnpm trellis doctor
pnpm trellis explain operation tasks.delete
```

Doctor should be able to show the exact MCP tool bound to the operation.
