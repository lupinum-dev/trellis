Start with one read-only MCP tool.

That proves the endpoint, bearer-token auth, runtime, access snapshot, and Convex call path. Writes and destructive tools come later, after the transport works.

If you are starting a new app, use the ladder:

```bash [Terminal]
pnpm dlx @lupinum/trellis init my-app
cd my-app
trellis add auth
trellis add workspace
trellis add mcp
```

That gives you the workspace baseline plus MCP files. If you are adding MCP to an existing workspace app, use this page as the checklist.

The rule is the same either way: MCP should call the same backend rules as the browser. Do not create a separate agent-only backend.

::steps{level="2"}

### Define the MCP endpoint

```ts [server/mcp/index.ts]
export default defineMcpHandler({
  name: 'mcp-reference',
  browserRedirect: '/',
})
```

Keep the handler small. The runtime does the real work.

### Authenticate requests in middleware

```ts [server/middleware/mcp-auth.ts]
export default defineEventHandler(async (event) => {
  if (!event.path?.startsWith('/mcp')) return

  const header = getHeader(event, 'authorization')
  if (!header?.startsWith('Bearer ')) return

  const token = header.slice('Bearer '.length)
  const hash = await sha256(token)

  const mcpAuth = await validateMcpToken(event, hash)
  if (mcpAuth) event.context.mcpAuth = mcpAuth
})
```

The middleware reads `Authorization: Bearer`, hashes the token, validates the hash in Convex, and puts the result on `event.context.mcpAuth`.

The raw token is transport input. It should not become product permission.

### Define the MCP runtime

```ts [server/mcp/runtime.ts]
import { createMcpConvexCaller, defineMcpApp, deniedMcpAccessSnapshot } from '@lupinum/trellis/mcp'

import { api } from '#trellis/api'
import { getMcpCaller, getMcpDelegation } from './auth'
import { todoPermissions } from '~~/convex/features/todos/permissions'

const deniedTodoAccess = deniedMcpAccessSnapshot(todoPermissions)

export const mcpRuntime = defineMcpApp({
  callConvex: async (event, { caller, actingFor }) =>
    createMcpConvexCaller(event, {
      caller,
      actingFor,
      isForwardedCaller: (candidate) => candidate.kind === 'agent',
    }),
  resolveCaller: async (event) => getMcpCaller(event),
  resolveActingFor: async ({ event }) => getMcpDelegation(event),
  resolveAccess: async ({ caller, convex }) => {
    if (caller.kind !== 'agent') return deniedTodoAccess

    return (
      (await convex.query(api.permissions.context.getAccessContext, {}))?.can ?? deniedTodoAccess
    )
  },
})
```

| Field              | What it does                                         |
| ------------------ | ---------------------------------------------------- |
| `callConvex`       | Creates the per-request Convex caller used by tools. |
| `resolveCaller`    | Turns middleware auth into the MCP caller.           |
| `resolveActingFor` | Optionally resolves the user the agent acts for.     |
| `resolveAccess`    | Builds a coarse access snapshot for tool visibility. |

The usual shape is:

- `caller`: the MCP agent, for example `agent:mcp_key_123`
- `actingFor`: the represented user, for example `user:u_42`

If your app does not support represented-user semantics, omit `resolveActingFor`.

### Export the tool factory

```ts [server/mcp/runtime.ts]
export const tool = mcpRuntime.tool
```

Tool files import this factory.

### Start with a read tool

```ts [server/mcp/tools/list-todos.ts]
import { api } from '#trellis/api'
import { listTodos } from '~~/shared/features/todos/contract'

import { tool } from '~/server/mcp/runtime'

export default tool.query({
  schema: listTodos,
  call: api.features.todos.domain.list,
  meta: {
    name: 'list-todos',
  },
})
```

This tool only reads. The called Convex handler still owns the real authorization decision.

::

## Schema boundaries

Keep schemas at the boundary that owns them:

- Convex validators are the backend argument contract.
- Edge-only Zod belongs beside the route, page, or component that owns that edge input.
- `shared/features/` is for contracts intentionally shared by Convex, Nuxt, and MCP.
- MCP tools project backend args into an MCP-safe schema when Trellis registers the tool.

The MCP tool should share backend intent. It does not need to reuse a frontend form schema.

## Why read-only first?

::caution
Destructive tools need more than transport wiring. They must be backed by an [operation](/docs/permissions/operations) with preview, and `destructiveOperations` must be configured.
::

Use this order:

1. Add one read-only `tool.query(...)`.
2. Add app writes through `tool.operation(...)`.
3. Add destructive tools after preview and confirmation work.

## Common pitfalls

- Starting with a destructive tool before the MCP auth path works.
- Treating the bearer token as product authorization.
- Reusing frontend form validation as the MCP tool contract.
- Adding agent-only backend handlers instead of calling the existing Convex path.
