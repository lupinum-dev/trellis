Pre-launch gate, not a tutorial. Walk through this before shipping.

## Environment

- [ ] `CONVEX_URL` points at the intended production deployment.
- [ ] `SITE_URL` matches the real public app origin.
- [ ] `BETTER_AUTH_SECRET` is set wherever auth is enabled (local env **and** Convex deployment — they must match).
- [ ] `CONVEX_SITE_URL` is set when the auth token exchange path needs it.
- [ ] `CONVEX_IDENTITY_FORWARDING_KEY` is set wherever identity-forwarding or MCP traffic exists.
- [ ] `CONVEX_IDENTITY_FORWARDING_KEY` is a long random server-only secret, not a short value or placeholder like `replace-me`.
- [ ] Trusted-forwarding traffic uses signed `_trellisForwarding` envelopes, not raw forwarding fields or identity-shaped public args.

## Policy and permissions

- [ ] `trellis.permissions.query` points at a real permission-context query when the UI depends on configured permissions.
- [ ] Route protection and permission guards are both exercised in staging (they fail for different reasons — don't skip either).
- [ ] Destructive operations have working preview and confirmation flows wherever Trellis requires them.
- [ ] Any `crossTenant` capabilities and `unsafe.*` seams are intentional and reviewed — every one has an explicit justification.
- [ ] Trusted-forwarding routes use server-owned principals and actingFor where needed, not an ad hoc webhook-bot shortcut.

## Runtime

- [ ] If SSR auth cache is enabled, its storage choice matches the deployment topology (not in-memory on a multi-node deploy).
- [ ] If any MCP tool uses `rateLimit`, the runtime provides an explicit external `rateLimitStore`.
- [ ] The MCP rate-limit store is atomic and shared across all production instances.
- [ ] If you use a custom MCP rate-limit store instead of `createRedisMcpRateLimitStore(...)`, you have independently reviewed its atomicity and failure behavior.
- [ ] Observability is configured for the production runtimes you care about, not "wired later."

## Docs and tests

- [ ] `pnpm run check` is green for normal repo handoff.
- [ ] `pnpm run release:verify` is green before release handoff.
- [ ] `pnpm run check:docs:links` is green if docs are part of the release.
- [ ] The relevant test paths have run for the changed area.
- [ ] The official lanes still generate and pass doctor: `public`, `personal`, `workspace`, and `workspace-mcp`.

## Verification gate

For this repo, the default adoption-contract gate is:

```bash [terminal]
pnpm run check
```

Before release handoff, run the broader release gate:

```bash [terminal]
pnpm run release:verify
```

The release gate covers formatting, lint, publish-surface checks, compatibility
matrix checks, type checks, contract tests, security tests, maintained example
doctor, starter fixture doctor, full repo/example tests, e2e, starter fixture
typecheck/build, Convex generated drift, package workspace references,
production audit, and build. It does not publish.
