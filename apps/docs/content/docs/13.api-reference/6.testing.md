Reference index for the public testing APIs. For usage flow, see the [testing section](/docs/testing/getting-started).

## Main exports

| Export                     | Purpose                                                  |
| -------------------------- | -------------------------------------------------------- |
| `convexTestConfig`         | Vitest config wrapper with the Convex edge-runtime setup |
| `createConvexTestModules`  | Module bridge for the generated Convex server            |
| `convexServerMock`         | Generated-server mock bridge used by Trellis apps        |
| `createTestContext`        | Per-test seed + caller API                               |
| `createObservationCapture` | Assert against emitted semantic events                   |

## Scope

These helpers make backend-handler and integration-style Trellis tests realistic without rebuilding runtime boundaries by hand. If a test needs to reach around Trellis to work, it is probably at the wrong layer.

`createTestContext(...)` returns seeded users from `seedTenant(...)` plus
trusted principal helpers:

- `asUser(...)` for explicit forwarded user callers.
- `asService(...)` for service/webhook callers, usually with `actingFor`.
- `asCaller(...)` for custom principal shapes such as MCP agents.
- `asAuthUser(...)` for auth-only handlers that intentionally read Convex auth
  identity instead of Trellis trusted forwarding.

Advanced component or bridge tests can pass `targetFunctionRef` when the Convex
function under test is an internal bridge wrapper but the trusted forwarding
target is the public root handler id. They can also pass `signedArgs` when a
bridge signs a payload that is intentionally narrower than the call args. Omit
both options for normal app tests.
