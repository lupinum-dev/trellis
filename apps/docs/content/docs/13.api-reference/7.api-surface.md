## API ladder

Use the smallest tier that matches the app. Higher tiers are supported when the
product needs them, but they are not day-one homework for smaller apps.

| Tier                          | APIs and concepts                                                                                                                                      | Use them when                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| Day-one public app            | `useConvexQuery`, `useConvexMutation`, `useConvex`, `operation.query`, `operation.publicMutation`, `query.public`, `mutation.public`, shared contracts | The app has public data and no signed-in workflow yet.                              |
| Auth app                      | Better Auth helpers, auth bootstrap, authenticated lanes, app-owned user identity                                                                      | The app needs signed-in users without tenant roles.                                 |
| Workspace app                 | `workspace` lanes, `workspaceScope`, guards, permissions, access context, record access, `_can`, tenant indexes                                        | The app needs roles, tenant isolation, or backend-owned permission projection.      |
| Server and webhook boundaries | `serverConvex*`, explicit auth modes, signed forwarding, service callers, transport proof                                                              | Nitro routes, webhooks, or trusted server callers must share backend authorization. |
| MCP agent lane                | MCP app/runtime, bearer keys, scoped tools, prompts, resources, sessions, rate limiting, operation-backed tools                                        | Agents are part of the product. Start from `workspace-mcp`.                         |
| Escape hatches                | `unsafe`, `publicWrite`, `crossTenant`, `actingFor`, raw `auth: 'none'`, handler-local public reads                                                    | A reviewed exception is narrower and better proven than the normal lane.            |

## Which API do I use?

- Vue component or composable: start with Nuxt auto-imports like `useConvexQuery()` and `useConvexMutation()`.
- Nuxt server route, server middleware, or Nitro endpoint: use server auto-imports or `@lupinum/trellis/server`.
- Convex backend code: use package subpaths such as `@lupinum/trellis/auth`, `@lupinum/trellis/backend`, or `@lupinum/trellis/args`.
- App-local generated Convex schema: use `#trellis/api`.
- Advanced MCP-only app wiring: use `#trellis/mcp` or `@lupinum/trellis/mcp` depending on runtime context.
- Bridge package-author code: use `@lupinum/trellis-bridge`; bridge helpers are not exported from the core Trellis package.

## Bridge package boundary

`@lupinum/trellis-bridge` is a separate package for package authors. Its root
entrypoint is for drift/install helpers; runtime authoring APIs live on explicit
subpaths.

| Import                              | Use it for                          |
| ----------------------------------- | ----------------------------------- |
| `@lupinum/trellis-bridge`           | Bridge drift/install helpers        |
| `@lupinum/trellis-bridge/component` | Component package author primitives |
| `@lupinum/trellis-bridge/convex`    | Convex-side bridge helpers          |
| `@lupinum/trellis-bridge/manifest`  | Bridge manifest helpers             |

Do not re-export bridge APIs from core Trellis just to shorten imports; the
separate package boundary is intentional.

## Important boundaries

- `@lupinum/trellis/server` is a **package export**.
- `serverConvexClearAuthCache` and `validateConvexArgs` are **Nuxt server auto-imports**, not package subpath exports.
- `#trellis/mcp` and `#trellis/server` are **generated Nuxt aliases**, not bare npm specifiers.
- `useAccess()` and `useAuthGuard()` are **config-driven auto-imports**, not package subpath exports.
- `@lupinum/trellis-bridge` is a separate package for packaged integration authors, not a root/core Trellis export.
- Identity forwarding uses signed `_trellisForwarding` envelopes; raw forwarding fields are not supported public args.
