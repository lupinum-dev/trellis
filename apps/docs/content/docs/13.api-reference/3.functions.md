Reference for the Trellis APIs used in Convex function files. Import app
builders from `@lupinum/trellis/app`. Use `@lupinum/trellis/backend` only for
advanced lower-level primitives such as custom callers, acting-for policy,
unsafe permits, and operation descriptors.

For the authoring walkthrough, read [Backend builders](/docs/permissions/backend-builders). This page stays terse.

Trellis has one public authorization model: keep business authorization on
operation `permission` metadata, lane choice, `load`, `authorize`, and
`handler`, and let `isolation` plus `services` enforce infrastructure
guardrails on `ctx.db`. Custom `guard` predicates are reserved for the
protected lane. Custom app-authored DB policy hooks are not part of the public
backend API.

## `defineTrellis(...)`

Primary entrypoint for building explicit query, mutation, and action lane
containers on top of Convex.

```ts
defineTrellis(builders, options?)
```

### Options

| Option                  | Purpose                                                    |
| ----------------------- | ---------------------------------------------------------- |
| `caller`                | How transport identity is resolved                         |
| `actingFor`             | How represented-user forwarding is validated               |
| `appIdentity`           | How a resolved caller maps to the app appIdentity          |
| `isolation`             | Tables that stay tenant-scoped by default                  |
| `services`              | Explicit high-trust service callers                        |
| `observability`         | Semantic event emission config                             |
| `destructiveOperations` | Required before registering destructive operations         |
| `trustedReplay`         | Durable JTI claim/complete/fail table for trusted writes   |
| `triggers`              | Convex triggers to install on the Trellis runtime path     |
| `onSuccess`             | Post-success side-work hooks for queries/mutations/actions |

### Returns

| Field                                                             | Purpose                                                                                     |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `query.public` / `mutation.public`                                | Public lanes                                                                                |
| `query.authenticated` / `mutation.authenticated`                  | Signed-in caller lanes without a workspace assumption                                       |
| `query.workspace` / `mutation.workspace`                          | Workspace lanes requiring concrete permission and projected `ctx.workspaceId` before `load` |
| `query.protected` / `mutation.protected`                          | Custom-guard lanes                                                                          |
| `action.public` / `action.authenticated`                          | Public and signed-in action lanes when actions are wired                                    |
| `action.workspace` / `action.protected`                           | Workspace and custom-guard action lanes when actions are wired                              |
| `transportMutation(...)` / `transportMutation.authenticated(...)` | Trusted transport execute lanes for bridge/MCP boundaries                                   |
| `internalQuery` / `internalMutation`                              | Internal lanes when internal builders are provided                                          |
| `internalTransportMutation(...)`                                  | Internal trusted transport lane when internal builders are provided                         |
| `query.unsafe` / `mutation.unsafe` / `action.unsafe`              | Explicit handler-level escape-hatch lanes                                                   |

### Database access

| Path                                                  | Use                                                                                 |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `ctx.db` in `query.public({ reads })` handlers        | Read-only facade limited to that handler's `reads` list                             |
| `ctx.publicWrite`                                     | Narrow methods from an operation-backed `publicWrite` capability                    |
| `ctx.db` in signed-in/workspace/custom-guard handlers | Default tenant/service-scoped database path                                         |
| `ctx.crossTenant`                                     | Narrow methods from a definition-visible cross-tenant capability                    |
| `query.unsafe` / `mutation.unsafe`                    | Explicit handler-level bypass lanes — require `permit: unsafe.permit(...)` metadata |

See [Tenant escape and unsafe access](/docs/permissions/cross-scope-and-raw-access).

::note
Tenant and service enforcement happen in the runtime so handlers do not have to remember manual tenant filters on every read. That runtime layer is infrastructure, not a public app-authorization API.
::

## `operation.*(...)`

Reusable product action for flows that need to work the same way in UI, server routes, and MCP.

```ts
operation.query({
  id,
  args,
  permission,
  load,
  handler,
})
```

### When to use

- Shared lane admission, `permission`, `load`, and `authorize` across preview +
  execute.
- One action needs stable identity across transports.
- Destructive action that needs Trellis-enforced preview/confirm.

### Builders

| Builder                         | Purpose                                                       |
| ------------------------------- | ------------------------------------------------------------- |
| `operation.query(...)`          | Read operation metadata plus handler implementation           |
| `operation.mutation(...)`       | Signed-in or workspace write operation                        |
| `operation.publicMutation(...)` | Public write operation with explicit `publicWrite` capability |
| `operation.destructive(...)`    | Destructive write with preview and confirmation semantics     |

### Destructive requirements

::warning
These must be present for `kind: 'destructive'`:

- `kind` set to `'destructive'`.
- `id` on the operation.
- `preview(...)` function.
- `destructiveOperations` configured in `defineTrellis(...)` before registration.
  ::

Preview is side-effect-free: it reads, loads, authorizes, and computes display
plus confirmation material. Execute re-runs lane admission, permission, load,
authorize, tenant binding, and drift checks before applying the handler. Preview
success is not an authorization grant.

### Projection helpers

| Helper                                                                | Purpose                                                                                                                               |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `mutation.authenticated(operation)` / `mutation.workspace(operation)` | Register the execute path on the lane that matches the caller model                                                                   |
| `previewOf(operation)`                                                | Produce the preview handler definition; register destructive previews on the same lane as execute when confirmation tokens are issued |
| `executeOperationRef(operation, ref)`                                 | Bind a backend execute ref to the operation metadata                                                                                  |
| `previewOperationRef(operation, ref)`                                 | Bind a backend preview ref to the operation metadata                                                                                  |

The lower-level `defineOperation` symbol remains available from `@lupinum/trellis/backend` for
advanced library and bridge authors. Application code should prefer the
app-facing `operation.*` builders because they remove backend-only guard shapes
from the normal authoring path.

## Handler context accessors

Handler context adds these Trellis APIs:

| Accessor                           | Returns                                             |
| ---------------------------------- | --------------------------------------------------- |
| `ctx.caller()`                     | Resolved transport identity                         |
| `ctx.appIdentity()`                | App-owned appIdentity derived from the caller       |
| `ctx.observe(...)`                 | Emits a semantic observability event                |
| `ctx.db`                           | Database API shaped by the current lane             |
| `ctx.crossTenant`                  | Present only when the handler declares a capability |
| `query.unsafe` / `mutation.unsafe` | Explicit handler-level escape hatch                 |

::note
Caller and appIdentity are async runtime facts, not compile-time assumptions. `await ctx.caller()` every time you need it inside a handler.
::
