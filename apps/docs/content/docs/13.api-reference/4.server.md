Reference for the Trellis helpers you use from Nitro routes, middleware, and other Nuxt server files. Each helper runs the same backend authorization path as a browser call — only the transport changes.

## `serverConvexQuery(event, fn, args?, options?)`

Run a protected Convex query from a Nitro server handler.

**Returns:** `Promise<TReturn>` — the query's return value, typed from the Convex function reference.

```ts [server/api/tasks.get.ts]
import { api } from '#trellis/api'

export default defineEventHandler(async (event) => {
  return await serverConvexQuery(event, api.tasks.list, { status: 'active' })
})
```

## `serverConvexMutation(event, fn, args?, options?)`

Run a protected Convex mutation from a Nitro server handler.

**Returns:** `Promise<TReturn>` — the mutation's return value.

```ts [server/api/tasks.post.ts]
import { api } from '#trellis/api'

export default defineEventHandler(async (event) => {
  const body = await readBody<{ text: string }>(event)
  return await serverConvexMutation(event, api.tasks.create, body)
})
```

## `serverConvexAction(event, fn, args?, options?)`

Run a protected Convex action from a Nitro server handler. Use this for handlers that hit external services (Stripe, email providers) or need non-reactive execution.

**Returns:** `Promise<TReturn>` — the action's return value.

```ts [server/api/billing/refund.post.ts]
import { api } from '#trellis/api'

export default defineEventHandler(async (event) => {
  const { chargeId } = await readBody<{ chargeId: string }>(event)
  return await serverConvexAction(event, api.billing.refund, { chargeId })
})
```

## `ServerConvexOptions`

Shared options across the three helpers above.

| Option       | Type                                               | Purpose                                                      |
| ------------ | -------------------------------------------------- | ------------------------------------------------------------ |
| `auth?`      | `'auto' \| 'required' \| 'none' \| TransportProof` | Auth mode or verifier-produced transport proof               |
| `authToken?` | `string`                                           | Explicit Convex auth token — skips session cookie resolution |

### Auth mode behavior

| Mode                          | Behavior                                                              |
| ----------------------------- | --------------------------------------------------------------------- |
| `auto`                        | Use the session cookie when available, call unauthenticated otherwise |
| `required`                    | Fail the call if auth can't be resolved                               |
| `none`                        | Never attach auth — for public Convex handlers only                   |
| `transportProof.server(...)`  | Signed server forwarding proof                                        |
| `transportProof.webhook(...)` | Signed webhook forwarding proof                                       |
| `transportProof.mcp(...)`     | Signed MCP forwarding proof                                           |

Forwarded caller and delegation evidence live inside the proof. Mutation and
action proofs must also declare replay intent with `domainIdempotency(...)`,
`jtiRedemption(...)`, or `operationConfirmation(...)`. JTI replay modes require
`defineTrellis({ trustedReplay: { table } })` on the target backend so Convex
claims the JTI before handler execution and marks it `completed` or `failed`
afterward. `domainIdempotency(...)` is declared in the transport proof, but the
target handler or operation still owns the domain idempotency check.

## `verifyHmacWebhookDelivery(event, options)`

Verify a server-to-server webhook using HMAC over timestamp, delivery id, and
the exact raw body. The helper reads the raw body once, validates the signature,
then parses the payload.

| Option             | Purpose                                              |
| ------------------ | ---------------------------------------------------- |
| `secret`           | Non-empty HMAC secret                                |
| `parse`            | Parse/validate the raw body after signature succeeds |
| `signatureHeader`  | Signature header name, defaults to `x-signature`     |
| `timestampHeader`  | Timestamp header name, defaults to `x-timestamp`     |
| `deliveryIdHeader` | Delivery id header name, defaults to `x-delivery-id` |
| `toleranceMs`      | Timestamp tolerance, defaults to five minutes        |

The returned delivery includes `id`, `body`, `rawBody`, `timestamp`, and
`signature`. Pass `delivery.id` into the backend/domain mutation that performs
the business write so duplicate delivery handling is transactional with the
write. Avoid route-side consume-before-dispatch stores.

## `requireDelegationBinding(options)`

Create short-lived `actingFor` evidence for a verified server, webhook, or MCP
caller that is allowed to act for one represented user.

| Option               | Purpose                                                   |
| -------------------- | --------------------------------------------------------- |
| `serviceId`          | Server-owned service or key id creating the delegation    |
| `targetUserId`       | Represented user id; produces `subject: user:<id>`        |
| `workspaceId`        | Tenant/workspace boundary the delegation is scoped to     |
| `purpose`            | Exact action family the target handler expects            |
| `grantSource`        | Backend policy source, such as `workspace-service-policy` |
| `expiresAt`          | Future timestamp when the delegation stops being valid    |
| `grantId?`           | Optional external grant/delivery/key id                   |
| `revocationVersion?` | Optional version the backend can compare for revocation   |
| `grantedBy?`         | Optional canonical subject that granted the delegation    |

Pass the result as `actingFor` inside a `transportProof.*(...)` object. This
helper validates shape and canonical subjects, but it is not the authorization
decision by itself. The target Convex `actingFor` resolver must call
`assertDelegationBinding(...)` or equivalent backend logic and re-check expected
service id, workspace, purpose, grant source, expiry, and any app-owned state
such as workspace membership, MCP key binding, account connection, or revocation
version.

### Failure behavior

- Missing Convex URL configuration throws a `ConvexCallError`.
- Auth resolution failures surface with error context attached.
- Convex error codes, status, category, and issues are preserved when present.

## `createServerConvexCaller(event, options?)`

Request-scoped caller for handlers that make multiple Convex calls — avoids repeating `event` and options on each line.

**Returns:** an object with `query`, `mutation`, and `action` methods.

| Method                | Purpose                                    |
| --------------------- | ------------------------------------------ |
| `query(fn, args?)`    | Run a query with the caller's auth mode    |
| `mutation(fn, args?)` | Run a mutation with the caller's auth mode |
| `action(fn, args?)`   | Run an action with the caller's auth mode  |

```ts [server/api/dashboard.get.ts]
import { createError } from 'h3'
import { api, internal } from '#trellis/api'
import { createServerConvexCaller } from '#trellis/server'

export default defineEventHandler(async (event) => {
  const id = getRouterParam(event, 'id')
  if (!id) {
    throw createError({ statusCode: 400, statusMessage: 'Missing dashboard id.' })
  }

  const convex = createServerConvexCaller(event, { auth: 'required' })
  const [runbook, incidents] = await Promise.all([
    convex.query(internal.runbooks.getForCurrentUser, { id }),
    convex.query(api.incidents.recent, { limit: 5 }),
  ])
  return { runbook, incidents }
})
```

::caution
The caller defaults to `auto`, matching the per-call helpers. Do not forward
caller or acting-for data from a route until the 0.3 proof API is available.
Forwarded principals are for verified server-to-server paths, not ordinary
browser-backed requests.
::

## What this surface is not

::warning
These helpers aren't a second authorization model. They change how a Nuxt server request reaches Convex — they don't replace Trellis guards, appIdentity resolution, tenant boundaries, or backend authorization. Every call still hits the handler's full protection path.
::
