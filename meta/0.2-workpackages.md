# Trellis 0.2 Workpackages

Status: Release prep
Date: 2026-06-03

This checklist is the implementation tracker for Trellis `0.2 Operation Ladder`.

Source of truth:

- [Roadmap](../ROADMAP.md)
- [RFC 0011: Hard-Cut Operation Ladder Release](./rfc/0011-hard-cut-operation-ladder-release.md)

Use this file to hand work to implementation agents. RFCs explain why the release should work this way;
this file tracks what must be built and how to prove each phase is done.

## Operating Rules

- [x] Prefer hard cutovers over compatibility paths.
- [x] Keep `@lupinum/trellis` as the Nuxt module entry.
- [x] Add `@lupinum/trellis/app` as the beginner app API.
- [x] Keep advanced APIs available but out of the beginner path.
- [x] Do not add permission override tables, role overlays, record sharing, audit tables, scoped DB
      wrappers, generic adapters, or public unauthenticated MCP defaults in `0.2`.
- [x] Every generated app must work before the user edits it.
- [x] Every added capability must have one canonical generated path and one doctor/conformance story.

## Done Definition

Trellis `0.2` is done when:

- [x] A user can start with `trellis init my-app`.
- [x] The same app can progressively add auth, workspace, and MCP.
- [x] One operation definition drives Convex, permission understanding, destructive safety, and MCP
      projection.
- [x] Workspace apps use validated `ctx.workspaceId` without scoped DB wrappers.
- [x] Auth bootstrap and MCP runtime setup are Trellis-owned by default.
- [x] Permissions are explainable before extra authorization tables exist.
- [x] Starters, examples, docs, and templates all teach the same path.
- [x] Ginko-style integrations can compose Trellis invariants without exposing Trellis as their public
      setup product.
- [x] `pnpm run release:verify` passes.
