# Trellis 0.2 Implementation Note

Status: Active implementation
Date: 2026-06-03

This note captures the current hard-cut drift discovered during the `0.2 Operation Ladder`
implementation. The authoritative tracker remains [0.2 workpackages](./0.2-workpackages.md).

## Current Beginner Path

The current working beginner path is:

1. install the Nuxt module through `@lupinum/trellis`;
2. author app backend behavior through `@lupinum/trellis/app`;
3. define operations with `operation.query(...)`, `operation.mutation(...)`, and
   `operation.destructive(...)`;
4. use `workspaceScope()` for workspace operations;
5. write visible Convex filters and writes with `ctx.workspaceId`.

The lower-level backend APIs still exist for advanced use, but they should not be taught as a
parallel first path in beginner docs, starter fixtures, or templates.

## Verified In This Slice

- `@lupinum/trellis/app` exports the beginner operation API.
- `workspaceScope()` injects only `ctx.workspaceId`; it does not add scoped DB wrappers.
- Public and personal starter fixtures define todo behavior through `operation.query(...)` and
  `operation.mutation(...)`.
- Canonical workspace starter fixtures use explicit `ctx.workspaceId` in reads and writes.
- Generated public, personal/auth, workspace, and workspace-MCP starter shapes typecheck.
- Generic resource generation emits `operation.*` templates from
  `@lupinum/trellis/app`; MCP-enabled workspace resource operations use
  `workspaceScope()` and `ctx.workspaceId` instead of hand-copying
  `appIdentity.workspaceId`.
- Maintained examples and starter fixtures use `@lupinum/trellis/app` for root
  `defineTrellis` setup.
- Access context handlers use `query.session(...)`; production-copyable source
  policy rejects `query.public(defineAccessContext(...))`.
- MCP tool authoring imports generated operation handles from
  `#trellis/operations/mcp`; generated operation-ref modules import
  `projectOperationRef` from `@lupinum/trellis/mcp`.
- Permission docs point static UI permission debugging at
  `trellis explain permission <key>` and `trellis permissions matrix` before
  runtime event inspection.
- Preset generation is covered by a mechanical equivalence test against the
  composed `trellis init` plus `trellis add` ladder.
- Generated MCP workspace slices enable Nitro async context, validate bearer
  tokens before MCP handling, inventory their intentional `auth: 'none'`
  server calls through doctor, and have route-level smoke coverage for real MCP
  `tools/list`/`tools/call` requests.
- `defineMcpApp(...)` defaults to `createMcpConvexCaller(...)`, so generated
  apps and maintained examples no longer copy `callConvex` or
  `isForwardedCaller` boilerplate for canonical `subject`-based MCP callers.
- Auth-enabled generated apps rely on module-owned client bootstrap. They keep
  the required `createUserIfNeeded` backend export, but do not ship an app
  bootstrap plugin or manually call the bootstrap mutation.
- The shadcn Trellis template passes its local `pnpm run check` gate against
  the 0.2 app framework shape.
- Ginko CMS passes `CI=true pnpm run check` after migrating component handlers
  to mandatory stable `id`, handler-local public `reads`, explicit
  `executeFunctionRef` on destructive operations, and Trellis testing helpers
  instead of raw forwarding envelopes.
